# Contributing

Use Node.js 24 and `npm ci`. Keep changes small and describe the visitor or maintainer problem they solve. Run `npm run check`, `npm run check:template`, and any relevant production-render or browser checks before opening a pull request.

Keep all business content fictional. Use reserved `example.com` addresses and documentation IP ranges. Do not add screenshots, exports, or settings from a real business. Preserve license notices for adapted code.

For accessibility changes, check keyboard navigation, narrow viewports, contrast, reduced motion, and the no-JavaScript fallback. For contact changes, test invalid input and provider failures as well as success.
